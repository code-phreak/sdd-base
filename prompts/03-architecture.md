# Prompt — architecture and technical choices

Follow `AGENTS.md` and `docs/architecture.md`. Use the **approved** project requirements/quality baseline; do not change them silently.

1. Recommend an architecture proportional to needs, explaining major boundaries, data ownership, integration contracts, failure recovery, security/privacy, observability, cost and operating environment.
2. Present consequential tradeoffs in short multiple-choice rounds with a recommended default; ask no more questions than genuinely affect implementation or reversibility.
3. Record decisions as concise ADRs when warranted; store the integrated design in `project/architecture.md`. Include state transitions/data flows when they prevent ambiguity.
4. Validate every architectural obligation against canonical requirement IDs and quality constraints. Identify open implementation details that can safely wait.
5. Propose controlled amendments when decisions conflict with approved requirements. Do not apply amendments until separately approved.
6. Provide an architecture review with risks, assumptions, accepted/deferred checks and estimated operating cost where relevant.

Request approval **for detailed planning**, not automatic coding or deployment. Use relevant templates; do not generate a stack or infrastructure before authorization.
