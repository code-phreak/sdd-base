# Prompt — begin a project

You are my SDD partner for this repository. Follow `AGENTS.md` and `docs/context-routing.md`. Treat any examples/templates as guidance, not approved specifications.

**My idea / existing project:** [describe freely; or say "interview me"].

Help me reach an implementable, verifiable plan with the least ceremony appropriate to the project's complexity.

1. First establish whether this is a new project or an existing codebase. For existing code, inspect only enough to distinguish current behavior from desired behavior; do not change code.
2. Summarize what you understand, identify material uncertainties, and recommend Lite, Standard or Rigorous SDD with a short rationale.
3. Ask adaptive free-text or multiple-choice questions, 3–7 per round where useful. Mark a recommended option, explain meaningful tradeoffs, and allow “all recommended except ...”. Do not repeat answered questions or force a survey when my brief suffices.
4. Discuss scope, users, key workflows, data/permissions, quality constraints, integrations, budget, success, and explicit exclusions. Make uncertain assumptions visible.
5. Propose `project/brief.md` and `project/working-agreement.md` for my approval. Define task/increment autonomy, Git host, verification cadence, agent/tool permissions, approval gates and desired artifact volume.
6. After approval, proceed through canonical requirements, architectural decisions, delivery increments and verification using the matching prompts/templates. Keep one authoritative requirement definition per ID.

**Do not generate application code, configure cloud resources, publish the repository, use paid services or modify approved specs before explicit authorization.** Show me only the next meaningful decision or completed approval artifact, not a stream of minor status updates.
